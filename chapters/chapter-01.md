## 1. 개념

### 서버를 빌린다는 것
React 앱의 정적 파일을 전달하거나 API를 실행하려면 CPU, 메모리, 디스크, 네트워크가 필요하다. 클라우드는 이런 자원을 API로 만들고 사용량에 따라 비용을 지불하는 방식이다. VM은 컴퓨터 한 대의 운영체제를 직접 관리하는 형태이고, 관리형 서비스는 운영 부담 일부를 제공자가 맡는다.

### 공동 책임과 실행 환경
관리형 DB를 선택해도 데이터 접근 권한, 스키마, 백업 요구사항은 사용자가 설계한다. IaaS에서는 게스트 OS 패치도 사용자 책임이다. 관리형이라고 모든 보안이 자동으로 해결되지는 않는다.

Linux에서는 현재 경로(`pwd`), 목록(`ls`), 파일 읽기(`cat`), 프로세스(`ps`), 환경 변수(`printenv`)를 구분한다. 프로세스는 실행 중인 프로그램이고 포트는 통신을 받는 논리적 번호다. 웹 서버가 꺼졌다면 방화벽을 열어도 응답하지 않는다. 파일 권한은 소유자·그룹·기타 사용자의 읽기/쓰기/실행 권한이다. 문제를 해결하려고 무조건 `chmod 777`을 사용하지 않는다.

## 3. 실습과 관찰

Cloud Shell에서 다음 읽기 명령을 실행한다. 로컬이나 클라우드 리소스를 생성하지 않는다.
```bash
pwd
ls -l
ps -ef | head
printf '%s\n' "$SHELL"
```
현재 디렉터리와 실행 중인 프로세스를 하나씩 기록한다. 정리할 유료 리소스는 없다.

## 4. 실전 시험형 예제

학습용 자체 제작 문제다. 실제 출제 문항이나 시험 덤프가 아니다.

### 문제 1 — 단일 선택

작은 HTTP API를 운영하며 OS 패치 부담을 최소화하려 한다. Kubernetes 기능은 필요 없다.

A. 모든 사용자에게 root를 준다
B. Cloud Run 같은 관리형 실행 환경을 검토한다
C. 전용 물리 서버를 구매한다
D. 직접 설치한 웹 서버 VM만 허용한다

### 문제 2 — 단일 선택

VM의 웹 포트가 허용되어 있지만 접속이 거부된다. 첫 진단으로 적절한 것은?

A. DB를 다중 리전으로 전환한다
B. 조직을 삭제한다
C. 서버 프로세스와 리스닝 포트를 확인한다
D. 모든 디스크를 포맷한다

### 문제 3 — 단일 선택

팀이 관리형 DB를 사용한다. 여전히 팀이 설계해야 할 것은?

A. 애플리케이션 계정의 최소 권한
B. 호스트 물리 디스크 교체 일정
C. 데이터센터 냉각 설비
D. 클라우드 사업자의 출입증 발급

<details>
<summary>개념 확인 정답과 시험형 문제 해설</summary>

### 개념 확인

1. VM 사용자에게 있다.

2. 실행 주체와 네트워크 통신 식별자다.

3. 데이터 접근 권한과 애플리케이션 설정이다.

### 시험형 예제

**1. B** — 운영 부담 최소화 조건에 맞는 관리형 실행 환경을 고른다. VM·물리 서버는 OS 운영이 늘고 root 부여는 배포 방식의 해결책이 아니다.

**2. C** — 연결 거부는 프로세스가 듣고 있는지부터 확인한다. 조직·디스크·DB 변경은 원인에 대한 근거가 없다.

**3. A** — 사용자 데이터와 권한은 서비스 이용자의 책임이다. 나머지는 제공자의 시설 운영 영역이다.

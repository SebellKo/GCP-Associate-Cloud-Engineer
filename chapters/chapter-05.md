# Chapter 05. API·할당량·위치와 자산 관리

공식 가이드 연결: **1.1** · 권장 2~3시간(통합 실습은 4~6시간)

## 1. 개념

### 사용 준비는 권한만으로 끝나지 않는다
서비스 API 활성화, IAM 권한, 결제 상태, 할당량, 해당 위치의 제품 지원을 모두 확인한다. quota는 프로젝트·리전·서비스 등에 적용되는 사용 한도이고 실제 물리 capacity와 다르다. quota가 충분해도 특정 존의 자원 부족으로 VM 생성이 실패할 수 있다.

Region은 지리적 위치, zone은 리전 안의 장애 격리 단위다. 리소스가 global/regional/zonal 중 어느 범위에 있는지 알아야 배치와 장애 영향을 판단한다. 데이터 거주 요건이 있으면 모든 제품이 모든 위치에 있다고 가정하지 않는다.

Cloud Asset Inventory는 조직의 자원과 정책을 찾고 변경을 추적하는 데 사용한다. Gemini Cloud Assist는 자원 분석과 작업 제안을 보조할 수 있다. AI의 제안은 실제 인벤토리, 권한, 실행 계획으로 검증한다. 할당량 증액 신청은 승인과 capacity 확보를 보장하지 않는다.

## 2. 개념 확인 문제

답을 먼저 적고 해설을 연다. 각 질문에 본인의 예시를 하나 붙인다.

1. quota와 capacity는 같은가?

2. 존 장애와 리전 장애 중 영향 범위가 보통 더 큰 것은?

3. AI 분석 결과를 그대로 적용해도 되는가?

## 3. 실습과 관찰

콘솔의 APIs & Services에서 Compute Engine API 상태를 확인한다. Quotas & System Limits에서 한 리전의 CPU quota와 사용량을 기록한다. `gcloud services list --enabled --project="$PROJECT_ID"`로 비교한다. 이번 단계는 조회만 한다. Asset Inventory는 접근 가능한 범위의 VM 목록을 검색하고 권한이 없으면 필요한 조회 역할을 조사한다.

## 4. 실전 시험형 예제

학습용 자체 제작 문제다. 실제 출제 문항이나 시험 덤프가 아니다.

### 문제 1 — 단일 선택

VM 생성 오류가 QUOTA_EXCEEDED다. 우선 조치는?

A. 해당 프로젝트·리전의 관련 quota 사용량을 확인한다
B. DNS 레코드를 삭제한다
C. 버킷 위치를 바꾼다
D. 방화벽을 전체 허용한다

### 문제 2 — 단일 선택

quota는 충분한데 특정 존에서 자원 부족 오류가 난다.

A. 프로젝트 이름을 바꾼다
B. API를 무조건 비활성화한다
C. Owner를 반복 부여한다
D. 요구사항이 허용하면 다른 존 또는 머신 유형을 검토한다

### 문제 3 — 단일 선택

여러 프로젝트의 VM과 IAM 설정을 중앙에서 찾으려 한다.

A. 로컬 브라우저 기록만 본다
B. Cloud DNS만 조회한다
C. 각 VM CPU를 증설한다
D. Cloud Asset Inventory를 사용한다

<details>
<summary>개념 확인 정답과 시험형 문제 해설</summary>

### 개념 확인

1. 아니다.

2. 리전 장애다.

3. 실제 설정·권한·계획으로 검증한다.

### 시험형 예제

**1. A** — 오류가 지정한 quota를 조사한다. DNS·방화벽·버킷 위치는 CPU 한도 원인이 아니다.

**2. D** — capacity 문제는 권한이나 이름 변경으로 해결되지 않는다. 배치·유형 대안을 검토한다.

**3. D** — 자산·정책 인벤토리를 제공하는 서비스가 맞다. 나머지는 중앙 자산 검색 기능이 아니다.

# Chapter 06. 결제·예산·비용 내보내기

[← 이전 장](chapter-05.md) · [전체 목차](../README.md) · [다음 장 →](chapter-07.md)

공식 가이드 연결: **1.2** · 권장 2~3시간(통합 실습은 4~6시간)

## 1. 개념

### 프로젝트와 비용 지불 주체
Cloud Billing account는 비용 지불을 연결한다. 프로젝트의 리소스 권한과 결제 계정 권한은 별개다. 결제 연결 작업에는 프로젝트 측 권한과 결제 계정 측 권한이 함께 필요할 수 있다. 예산은 프로젝트별 또는 결제 계정 범위로 구성해 비용 추이를 감시한다.

일반적인 alerts-only budget은 임계값을 넘으면 알림을 보내며 자동 비용 차단 장치가 아니다. 최신 별도 spend cap 기능의 지원 서비스·제약과 구분해야 한다. 이 교재의 일반 예산 실습은 alerts-only 기준이다. 과금 데이터와 알림에는 지연이 있으므로 정확히 임계값에서 중단된다고 가정하지 않는다.

Billing export를 BigQuery로 보내면 일별·서비스별 비용을 SQL로 분석할 수 있다. 내보내기는 조기에 설정하고 모든 과거 데이터가 소급된다고 기대하지 않는다. 비용에는 실행 자원뿐 아니라 저장, 요청, 전송, 로그 보관, 백업도 포함된다. stopped VM에도 디스크 등은 남을 수 있다.

## 2. 개념 확인 문제

답을 먼저 적고 해설을 연다. 각 질문에 본인의 예시를 하나 붙인다.

1. alerts-only 예산이 모든 자원의 사용을 중지하는가?

2. VM 정지만으로 모든 요금이 없어지는가?

3. 비용 SQL 분석에 적합한 내보내기 대상은?

## 3. 실습과 관찰

실습 프로젝트에 월 alerts-only 예산을 설정하고 50%·90%·100% 알림 수신 대상을 확인한다. 금액은 본인이 감당할 수 있는 한도로 정한다. Billing Reports에서 서비스별 비용을 조회한다. BigQuery export는 데이터셋 위치와 과금 영향을 검토한 뒤 선택 실습한다. 예산 자체를 삭제해도 자원은 삭제되지 않는다.

## 4. 실전 시험형 예제

학습용 자체 제작 문제다. 실제 출제 문항이나 시험 덤프가 아니다.

### 문제 1 — 단일 선택

팀이 alerts-only 예산을 10달러로 설정했다. 10달러 초과 요금을 막는다고 믿는다.

A. VM을 더 만든다
B. 알림 이메일을 삭제한다
C. 어떤 서비스든 즉시 자동 종료된다고 설명한다
D. 알림과 차단을 구분하고 별도로 자원 정리·사용 제한을 설계한다

### 문제 2 — 단일 선택

서비스별 매일 비용을 SQL로 분석하려 한다.

A. Cloud DNS 레코드를 늘린다
B. 버킷을 공개한다
C. 모든 VM에 SSH한다
D. Cloud Billing export를 BigQuery에 구성한다

### 문제 3 — 단일 선택

프로젝트 관리자는 결제 연결을 못 한다. 적절한 점검은?

A. 프로젝트 결제 변경 권한과 결제 계정 사용 권한을 함께 확인한다
B. CPU quota만 늘린다
C. 모든 로그를 지운다
D. 서브넷을 확장한다

<details>
<summary>개념 확인 정답과 시험형 문제 해설</summary>

### 개념 확인

1. 아니다.

2. 디스크·IP 등 잔존 자원 비용이 있을 수 있다.

3. BigQuery다.

### 시험형 예제

**1. D** — 일반 예산은 경보 기능이다. 자동 종료 보장은 틀리고 알림 삭제·VM 증설은 비용 통제에 역행한다.

**2. D** — 결제 데이터 내보내기가 직접적이다. DNS·공개화·SSH는 비용 테이블을 제공하지 않는다.

**3. A** — 결제 연결에는 양쪽 범위의 권한이 관계한다. CPU·로그·서브넷은 이 권한 오류와 무관하다.

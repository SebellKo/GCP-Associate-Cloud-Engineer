## 1. 개념

### VM 선택과 수명 주기
VM을 만들 때 머신 유형, 이미지, 디스크, 네트워크, 위치, 서비스 계정, 가용성 정책을 선택한다. 머신 유형은 CPU·메모리를 결정하고 이미지는 OS와 초기 소프트웨어의 출발점이다. 부팅 디스크 자동 삭제 여부를 확인해야 VM 삭제 후 데이터가 남는지 알 수 있다.

VM이 RUNNING이라는 사실은 앱이 정상이라는 뜻이 아니다. 앱 프로세스, 포트, 네트워크와 권한을 따로 확인한다. 외부 IP 없이도 Identity-Aware Proxy(IAP) TCP forwarding을 통해 접속할 수 있지만 IAP 권한, OS Login 권한, IAP 주소 범위에서 SSH를 허용하는 방화벽, 대상 VM 설정이 필요하다.

OS Login은 IAM으로 Linux 계정 접근을 관리한다. VM 관리자 권한과 로그인 권한은 목적이 다르고, 연결된 서비스 계정 사용 권한 등 추가 요구도 확인한다. VM Manager는 OS 인벤토리·패치·구성 관리를 지원하며 VM 자동 확장 서비스가 아니다.

## 3. 실습과 관찰

[VM 실습](../labs/vm.md)을 수행한다. 전용 custom VPC와 IAP SSH 규칙을 만들고 외부 IP 없는 VM에 접속한다. 성공 기준은 VM 내부에서 hostname을 확인하는 것이다. VM·디스크는 시간 과금이 있으므로 같은 세션에 삭제 절차까지 수행한다.

## 4. 실전 시험형 예제

학습용 자체 제작 문제다. 실제 출제 문항이나 시험 덤프가 아니다.

### 문제 1 — 단일 선택

운영 VM에 공인 IP를 주지 않고 관리자가 SSH해야 한다.

A. 모든 사용자에게 SSH 개인키를 공유한다
B. 인터넷 전체에 22번을 연다
C. IAP TCP forwarding과 필요한 IAM·OS Login·방화벽을 구성한다
D. 버킷을 공개한다

### 문제 2 — 단일 선택

VM은 실행 중인데 앱이 응답하지 않는다.

A. 실행 상태만 보고 정상 처리한다
B. 결제 계정을 새로 만든다
C. 폴더를 삭제한다
D. 앱 프로세스·리스닝 주소·로그와 방화벽을 점검한다

### 문제 3 — 단일 선택

수십 VM의 OS 패치 현황을 관리하려 한다.

A. Cloud DNS를 사용한다
B. VM Manager를 검토한다
C. Pub/Sub 메시지만 삭제한다
D. Nearline으로 바꾼다

<details>
<summary>개념 확인 정답과 시험형 문제 해설</summary>

### 개념 확인

1. OS 출발점과 CPU·메모리 사양이다.

2. IAP 같은 경로를 사용할 수 있다.

3. OS 관리와 VM 그룹 운영이다.

### 시험형 예제

**1. C** — IAP 경로와 권한을 함께 구성한다. 전체 공개와 키 공유는 요구에 부합하지 않고 버킷은 무관하다.

**2. D** — 컴퓨트 실행과 앱 건강 상태는 별개다. 나머지는 원인 검증을 건너뛴다.

**3. B** — VM Manager의 OS 관리 기능이 맞다. DNS·스토리지 등급·메시지 삭제는 패치 관리가 아니다.

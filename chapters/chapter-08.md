## 1. 개념

### 실행 자원과 영속 데이터를 분리한다
Persistent Disk와 Hyperdisk는 VM용 블록 스토리지다. 지원 머신·리전·성능 구성을 확인해 선택한다. zonal disk와 regional disk는 장애에 대한 배치 범위가 다르다. Local SSD는 고성능 임시 저장에 적합하지만 중요한 데이터의 유일한 사본으로 사용하지 않는다.

스냅샷은 디스크 데이터의 복구 지점이고, 커스텀 이미지는 새 VM을 일관된 OS·소프트웨어 구성으로 시작하는 데 적합하다. 스냅샷을 만들었다는 사실만으로 앱 수준 일관성이 보장되지는 않는다. DB 쓰기 정지나 앱 일관성 절차를 확인한다. 스냅샷 스케줄은 반복 백업을 자동화한다.

RPO는 허용 가능한 데이터 손실 시간, RTO는 복구 목표 시간이다. 복제는 최신 상태를 다른 곳에 유지하지만 잘못된 삭제도 전파할 수 있다. 백업·복제·고가용성을 구분하고 실제 복원을 시험한다.

## 3. 실습과 관찰

VM 실습 중 테스트 파일을 만들고 부팅 디스크 이름을 `gcloud compute instances describe`로 확인한다. 콘솔에서 해당 디스크의 스냅샷을 만든다. 스냅샷으로 새 디스크를 만들어 원본과 구분하고 파일 복원을 확인한다. 스냅샷·복원 디스크는 VM 삭제와 별개로 삭제한다. 개인 중요 데이터에는 실행하지 않는다.

## 4. 실전 시험형 예제

학습용 자체 제작 문제다. 실제 출제 문항이나 시험 덤프가 아니다.

### 문제 1 — 단일 선택

동일 OS와 패키지를 가진 VM 30대를 반복 배포한다.

A. 검증된 커스텀 이미지를 사용한다
B. 모든 파일을 Local SSD에만 둔다
C. DNS에 패키지 목록을 넣는다
D. 매번 수동 SSH로 설치한다

### 문제 2 — 단일 선택

실수로 삭제한 데이터가 복제본에서도 사라졌다. 앞으로 필요한 것은?

A. CPU quota 증액
B. 서비스 계정을 Owner로 변경
C. 별도 복구 지점과 복원 검증
D. 복제만 더 자주 실행

### 문제 3 — 단일 선택

중요 데이터를 Local SSD 하나에만 보관하려 한다.

A. VM 정지 후에도 무조건 영구 보존된다고 가정한다
B. 스냅샷 없이 이미지 이름만 기록한다
C. 로그를 삭제한다
D. 내구성 있는 저장소와 백업에 원본을 보관한다

<details>
<summary>개념 확인 정답과 시험형 문제 해설</summary>

### 개념 확인

1. 손실 가능한 데이터 시간과 복구 소요 목표다.

2. 논리적 삭제·손상도 복제될 수 있어 아니다.

3. 커스텀 이미지를 검토한다.

### 시험형 예제

**1. A** — 이미지는 재현 가능한 VM 출발점을 제공한다. 수동 설치는 편차가 생기고 Local SSD·DNS는 배포 표준화 수단이 아니다.

**2. C** — 논리적 오류와 시점 복구에는 백업이 필요하다. 복제 빈도·권한·CPU는 과거 상태를 복원하지 못한다.

**3. D** — Local SSD는 임시 데이터 용도다. 이름 기록이나 로그 삭제는 데이터 보존이 아니며 영구 보존 가정은 틀리다.

## 1. 개념

### 여러 VM을 하나의 운영 단위로 다룬다
Instance template은 VM 사양을 정의하는 변경 불가능한 템플릿이다. Managed Instance Group(MIG)은 템플릿에서 VM을 생성하고 일관된 그룹으로 관리한다. 새 설정은 새 템플릿과 rolling update로 배포한다. regional MIG는 한 리전의 여러 존에 배치해 존 장애 영향을 줄인다.

Autoscaling은 부하에 따라 VM 수를 조정한다. Autohealing은 건강하지 않은 VM을 교체한다. Load balancer의 health check는 요청을 보낼 대상을 고르는 데 쓰이며 autohealing의 교체 목적과 구분한다. 초기화가 느린 앱은 초기 지연 설정을 검토한다.

Spot VM은 저렴할 수 있지만 중단될 수 있으므로 체크포인트·재시도 가능한 작업에 적합하다. 결제 API처럼 중단을 감당할 수 없는 단일 인스턴스의 유일한 실행 자원으로 선택하지 않는다. 커스텀 머신 유형은 CPU·메모리 비율을 조절하지만 실제 사용률을 측정한 뒤 결정한다.

## 3. 실습과 관찰

유료 생성 대신 먼저 설계 실습을 한다. CPU 부하 증가, 앱 프로세스 장애, 존 장애별로 autoscaling/autohealing/regional MIG 중 대응을 적는다. 선택 실습: 콘솔에서 새 템플릿으로 최소 1대·최대 2대 MIG를 만들고 업데이트 화면을 확인한다. 끝나면 MIG를 먼저 삭제하고 템플릿·디스크·LB 잔존 여부를 확인한다.

## 4. 실전 시험형 예제

학습용 자체 제작 문제다. 실제 출제 문항이나 시험 덤프가 아니다.

### 문제 1 — 단일 선택

요청 증가 시 VM 수를 늘리고 싶다.

A. MIG autoscaling을 설정한다
B. 스냅샷만 매시간 만든다
C. DNS TTL만 늘린다
D. 이미지를 공개한다

### 문제 2 — 단일 선택

한 존 장애에도 웹 서비스를 유지해야 한다.

A. 한 VM의 이름을 바꾼다
B. 스냅샷 보관을 끈다
C. 여러 존의 regional MIG와 적절한 LB를 구성한다
D. 동일 존 VM만 복제한다

### 문제 3 — 단일 선택

몇 시간 걸리는 이미지 처리 작업을 체크포인트에서 재시작할 수 있다. 비용 절감 선택은?

A. Owner 역할을 준다
B. 백업을 지운다
C. 중단 불가 단일 VM을 최고 사양으로 고정한다
D. Spot VM과 재시도·체크포인트를 사용한다

<details>
<summary>개념 확인 정답과 시험형 문제 해설</summary>

### 개념 확인

1. 규모 조정과 비정상 VM 교체다.

2. 아니다.

3. 중단·재시도 가능한 배치다.

### 시험형 예제

**1. A** — 부하 기반 규모 조정은 autoscaling이다. 백업·DNS·이미지 공개는 처리 VM 수를 자동 조정하지 않는다.

**2. C** — 존 분산과 요청 분배가 필요하다. 같은 존 복제는 공통 장애를 피하지 못한다.

**3. D** — 중단을 처리할 수 있어 Spot의 절감 특성을 활용한다. 고정 최고 사양·백업 삭제·Owner는 요구에 맞는 절감 설계가 아니다.

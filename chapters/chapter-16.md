## 1. 개념

### 이미지와 실행 인스턴스를 분리한다
컨테이너 이미지는 앱 코드·런타임·파일을 포함하는 배포 산출물이고 컨테이너는 그 이미지의 실행 인스턴스다. 컨테이너가 VM처럼 독립 게스트 커널을 갖는다고 생각하지 않는다. 상태 데이터는 적절한 외부 저장소로 분리한다.

Artifact Registry는 이미지와 패키지를 저장한다. Cloud Build는 소스에서 이미지를 만들거나 작업을 실행한다. build identity, deploy identity, runtime identity를 구분해야 한다. 빌드 성공이 런타임의 DB 접근 권한을 보장하지 않는다.

태그는 재지정될 수 있다. 정확한 배포 재현에는 digest를 기록한다. 비밀은 이미지 레이어나 저장소에 넣지 않고 Secret Manager 같은 런타임 전달 경로를 쓴다. GKE의 이미지 pull은 관련 노드 identity와 registry 권한을 확인하며 Pod의 API 호출용 identity와 혼동하지 않는다.

## 3. 실습과 관찰

[통합 실습](../labs/capstone.md)의 샘플 Go 서버와 Dockerfile을 읽는다. build가 실행 파일을 만드는 단계, registry가 산출물을 저장하는 단계, Cloud Run이 실행하는 단계임을 적는다. 선택 실행 후 Artifact Registry repository·이미지·Cloud Build 로그 저장 자원의 비용과 삭제를 확인한다.

## 4. 실전 시험형 예제

학습용 자체 제작 문제다. 실제 출제 문항이나 시험 덤프가 아니다.

### 문제 1 — 단일 선택

새 이미지 배포를 나중에 정확히 재현해야 한다.

A. 이미지 digest와 배포 설정을 기록한다
B. VM 이름만 적는다
C. latest 태그만 기억한다
D. 컨테이너 로그를 모두 지운다

### 문제 2 — 단일 선택

이미지에 DB 비밀번호가 들어갔다. 적절한 대응은?

A. 공개 repository로 옮긴다
B. 비밀을 회전하고 이미지에서 제거한 뒤 안전한 런타임 전달을 구성한다
C. 이미지 태그만 바꾼다
D. 비밀번호를 README에 적는다

### 문제 3 — 단일 선택

GKE에서 ImagePullBackOff가 발생한다.

A. DB 백업을 복원한다
B. Pod CPU만 늘린다
C. 이미지 경로·존재·pull 주체의 Registry 권한·네트워크를 확인한다
D. DNS zone을 무조건 삭제한다

<details>
<summary>개념 확인 정답과 시험형 문제 해설</summary>

### 개념 확인

1. 배포 산출물과 실행 인스턴스다.

2. 아니다. digest를 기록한다.

3. 필요한 권한과 책임이 다르다.

### 시험형 예제

**1. A** — digest는 특정 이미지 내용을 식별한다. 변경 가능한 latest나 VM 이름은 배포 내용을 고정하지 않는다.

**2. B** — 노출된 비밀은 회전과 배포 방식 수정이 필요하다. 태그 변경은 레이어의 비밀을 제거하지 않는다.

**3. C** — 이미지를 가져오는 경로를 조사한다. CPU·백업·무조건 삭제는 원인 검증이 아니다.

## 1. 개념

### HTTP 호출과 이벤트를 구분한다
Cloud Run functions는 함수 단위 배포를 지원한다. Eventarc는 지원되는 서비스 이벤트를 대상 서비스로 전달하는 경로를 구성한다. 예를 들어 객체 업로드 이벤트를 받아 썸네일을 만드는 처리를 설계할 수 있다. Pub/Sub는 생산자와 소비자를 느슨하게 연결하고 backlog를 완충한다.

이벤트 처리는 중복·재시도·순서와 실패를 고려한다. 같은 이벤트로 결제가 두 번 일어나지 않도록 event ID나 업무 키로 멱등성을 설계한다. 영구 실패는 dead-letter 경로와 관측 지표를 준비한다. 모든 이벤트 제품이 기본으로 엄격한 순서와 exactly-once 업무 처리를 제공한다고 가정하지 않는다.

트리거 identity, 이벤트 생산 서비스 identity, 목적지 호출 권한을 구분한다. 배포가 됐어도 전달 경로에 권한이 없으면 처리되지 않는다. 이벤트 위치 제약과 대상 위치 호환성도 확인한다. 긴 작업은 요청 연결에 묶지 않고 지원되는 비동기 실행 모델을 검토한다.

## 3. 실습과 관찰

설계 실습: object finalized 이벤트→Eventarc→Cloud Run 처리의 identity와 권한을 적는다. 같은 이벤트를 두 번 보냈을 때 결과 파일 이름이 중복되지 않게 설계한다. 선택 배포 시 임시 bucket·trigger·service만 사용하고 trigger부터 제거한다. 저장소와 출력 객체도 함께 삭제한다.

### 개념 확인

1. 같은 이벤트가 다시 와도 업무 결과 중복을 막기 위해서다.

2. 이벤트 라우팅과 데이터 저장은 별개다.

3. 트리거·목적지 권한을 따로 확인한다.

### 시험형 예제

**1. C** — 지원 이벤트 전달 경로를 사용한다. DNS·이미지 복사는 이벤트 소비가 아니고 수동 처리는 자동화 요구에 맞지 않는다.

**2. C** — 중복 전달을 견디는 업무 설계가 필요하다. 자원 증설·로그 삭제·공개화로 중복 결과를 막지 못한다.

**3. A** — 전달 단계의 호출 identity를 점검한다. 저장 등급·이름 변경·백업 삭제는 접근 권한을 주지 않는다.

## 1. 개념

### 증거를 모으고 작은 변경부터 한다
먼저 영향 범위와 시작 시각을 확인하고 최근 배포·권한·네트워크 변경을 비교한다. Cloud Trace는 요청 경로와 지연, Cloud Profiler는 코드 자원 사용, Query Insights와 index advisor는 DB 성능 조사에 도움을 준다. Personalized Service Health는 사용자 자원과 관련된 서비스 이벤트를 확인하는 경로다.

Active Assist는 자원 사용과 권한 등 최적화 제안을 지원한다. 낮은 사용률만 보고 운영 자원을 삭제하지 말고 주기적 부하·예약 작업·가용성 요구를 확인한다. Cloud Hub는 앱 상태와 운영 이벤트를 통합해 보는 데 활용한다. Gemini Cloud Assist가 제시한 원인도 로그·metric·변경 이력으로 검증한다.

GPU는 병렬 가속, TPU는 지원되는 ML 워크로드 가속에 특화된다. 가격만이 아니라 프레임워크·위치·quota·가용성을 확인한다. Agent Runtime(이전 Vertex AI Agent Engine), Workbench, Cloud Workstations는 각각 에이전트 실행·노트북·개발 환경의 역할을 구분한다. 생성 후 중지·삭제와 연결 스토리지 비용을 확인한다.

## 3. 실습과 관찰

사고 연습: 새 revision 배포 직후 지연과 5xx가 증가했다. 이전 revision 비율을 되돌리기 전후에 비교할 metric·로그·DB 상태를 적는다. Health dashboard와 Active Assist에서 본인 범위의 항목을 읽는다. GPU·TPU·Agent Runtime·Workbench는 개념 및 콘솔 확인만 기본으로 하며 생성하지 않는다.

## 4. 실전 시험형 예제

학습용 자체 제작 문제다. 실제 출제 문항이나 시험 덤프가 아니다.

### 문제 1 — 단일 선택

배포 직후 오류율이 급증했다. 안전한 첫 대응은?

A. 모든 DB를 삭제한다
B. 전체 IAM을 공개한다
C. 지표·로그를 확인하며 검증된 revision으로 트래픽 복원을 검토한다
D. 감사 로그를 끈다

### 문제 2 — 단일 선택

여러 앱에서 특정 Google 서비스 오류가 동시에 발생한다.

A. Personalized Service Health와 관련 로그를 확인한다
B. 버킷 등급만 바꾼다
C. 모든 VM을 무조건 재생성한다
D. 비밀번호를 README에 쓴다

### 문제 3 — 단일 선택

최적화 도구가 저사용 VM 삭제를 제안했다. VM은 월말 배치를 수행한다.

A. 낮은 평균만 보고 즉시 삭제한다
B. 모든 디스크를 포맷한다
C. 주기적 사용과 업무·복구 요구를 확인해 권장안을 평가한다
D. 로그를 전부 지운다

<details>
<summary>개념 확인 정답과 시험형 문제 해설</summary>

### 개념 확인

1. 서비스 상태·영향 자원·로그·metric·변경 이력이다.

2. 가용성·보안·비용 조건으로 검증한다.

3. 개발 환경과 서비스 실행 목적이 다르다.

### 시험형 예제

**1. C** — 최근 변경과 오류의 관계를 확인하고 가역적 복구를 검토한다. 데이터 삭제·관측 제거·공개화는 장애를 키운다.

**2. A** — 공통 제공자 장애 여부를 확인한다. 재생성·비밀 노출·저장 등급은 공통 원인 증거가 아니다.

**3. C** — 평균 지표가 주기적 업무 필요를 배제하지 않는다. 즉시 파괴나 증거 삭제는 부적절하다.
